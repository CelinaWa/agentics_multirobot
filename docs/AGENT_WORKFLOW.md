# Agent 在整个流程里做什么

> 写于 2026-10-27。和 `REAL_ROBOT_WORKFLOW.md`（你在现场做什么）对着看：那边是你的清单，这边是 agent 的清单。
> 依据：RAX 真机分支 `2/homebody/.cache/rax-g1real` 里给 agent 的说明书 `auto_research_agent/AGENTS.md`、G1 的机器人定义 `services/workspace/setup.py`、技能目录 `agent_skills/`、工具定义 `services/g1sonic/tools.py`，以及 `3/eng` 里用同一套工具跑的 sim 实验。

---

## 一、agent 是什么

- 一个 **Claude Code 会话**，运行在 RAX 主机上一个**没有任何机器人 SDK 的 Python 环境**里。它能用的"手脚"只有 11 个机器人工具（下表），全部经过 robot service 的安检；它写的任何脚本也只能调这 11 个工具。
- 它能看到：头部相机的彩色图和深度图（`g1_observe`）、机器人状态（`g1_status`：关节角、倾斜、钥匙、故障、预算）、每次动作后的反馈（跟踪误差、倾斜）。
- 它看不到：真值位置、它自己走了多远（只有命令值）、你的脸。它不知道你在旁边，除非你在终端里告诉它。

| 工具 | 干什么 | 会不会让机器人动 |
|---|---|---|
| `g1_status` | 关节、倾斜、控制模式、钥匙、故障、剩余预算 | 不会 |
| `g1_observe` | 拍一张彩色 + 深度图 | 不会 |
| `g1_pixel_to_position` | 图上一个像素 → 机器人坐标系里的三维位置 | 不会 |
| `g1_hold` | 停在当前姿势；第一次调用时启动控制（你按过 `s` 就直接成功） | 停住 |
| `g1_step` | 发 1 到 100 帧（50 Hz，最多 2 秒）全身目标姿势，末尾停住 | 动手臂、腰、手 |
| `g1_hand_shape` | 定义"张开"和"握紧"的 Dex3 手指姿态 | 不会 |
| `g1_walk` | 往前走 X 米 / 转 Y 度（带热身、分段、`carry` 冻住手臂） | 走路 |
| `g1_crouch` | 腿部下蹲（骨盆最多降 0.32 m，可带前倾）再站起；手够不到地面 | 动腿 |
| `g1_free_space_move` / `g1_execute_motion_plan` | 先规划一条手臂轨迹（避碰），再执行 | 动手臂 |
| `request_operator` | 向你提请求：`help`（卡住了）或 `reset`（请把场景复位） | 不会；它等你回答 |

## 二、按时间顺序：你做一步，它做什么

| 你（`REAL_ROBOT_WORKFLOW.md` 清单 A） | agent 这时在做什么 |
|---|---|
| 1 到 6：吊起、开机、开相机、开 SONIC | 还没启动 |
| 7：`configure_session.py --task-file task.md` | 还没启动。你的 `task.md` 会变成它工作目录里的 `TASK.md` |
| 8：`start_agent.sh` | **启动。** 第一句指令是固定的："读 AGENTS.md、MCP_SESSION.md、TASK.md，调 status，按 AGENTS.md 的流程做"。它依次：① 读说明书（安全规矩、流程）② 读 `TASK.md`（你的任务）③ 读 `memory/PROGRESS.md`、`skill-library/INDEX.md`（以前的 session 留下的进度和技能，有就复用）④ 调 `g1_status`：这时 SONIC 还没开始控制，返回"没有本体状态"，它知道这是正常的 ⑤ **必读两份技能**：`robot-interface`（40 维姿势帧怎么填、钥匙/停止是什么意思、安检规则）和 `controller-field-guide`（在 SONIC 上怎么走、怎么转、怎么伸手、碰到东西时看什么反馈）⑥ 可能先 `g1_observe` 看一眼场景 |
| 9：按 `s`，机器人站起来（不踏步：SONIC 直接盯着站立参考动作平衡） | 它不知道你按了。它想动的第一个工具调用（通常是 `g1_hold`）会被拒绝："没上钥匙"。于是它调 **`request_operator`（kind `help`）**，内容大意是"请上钥匙、确认周围清空"，然后**等**。dashboard 和控制台都能看到这条请求 |
| 10、11：检查完毕，按空格上钥匙，`r` 回答它那条 `help` 请求 | 它的 `g1_hold` 通过：机器人已经在控制里，这个 hold 什么都不改，只是"定在现在的姿势"。（你没按 `s` 就直接上钥匙的话，这个 hold 才是启动控制的那一下：它走的是老的规划器路线，机器人会在带子里踏几步站稳，大约 15 秒；所以先按 `s`。）接着 `g1_status` 看到 streamed 模式、倾斜角、关节角，**从测得的关节角出发**做第一个小动作 |
| 12：第一次走路后摘带子 | 它的第一次 `g1_walk` 会自动先左右各扭 15 度热身再走；走完它 `g1_observe` 量一下走到了哪（它知道走路距离不准，`controller-field-guide` 里写了） |
| 13：任务进行中 | 见下一节 |
| 空格暂停 | 正在做的动作 20 ms 内停住。它下一个工具调用被拒，拒绝原因里写着"操作员暂停"，它会停下来等（规矩：拒绝是一堵墙，不许绕），一般会 `request_operator` 问能不能继续 |
| 空格恢复（控制台显示有待回答请求时再按 `r`） | 它先 `g1_status` 和 `g1_observe`（规矩：停过之后先看再动），再接着做。`r` 不是每次恢复都要按：只有它在暂停期间调了 `request_operator` 在等你，`r` 才有东西可答；没有请求时 `r` 显示 "no open request to answer" |
| `o` 停止 / 摔倒自动拔钥匙 | 它收到"已停止 / 故障"的回复。规矩：**不许自己做任何恢复动作**，只能 `request_operator`（`help`）报告它看到了什么、最后发了什么帧，然后等你重新上钥匙 |
| 15：你 Ctrl-C | 它被结束；之前写在 `memory/` 和 `skill-library/` 里的东西都在 |

## 三、任务进行中它的工作方法（AGENTS.md 规定的四步）

**第 1 步：先自己把任务做一遍（手动）。** 技能 `manual-robot-control`。循环是：
`g1_observe` 看图 → 在图上找到物体，`g1_pixel_to_position` 得到三维位置 → 算一个小动作（从 `g1_status` 的测得关节出发，不超过 2 秒，末尾停住）→ `g1_step` 发出去 → 读回复里的 `transition.feedback`（跟踪误差、倾斜）→ 再 `g1_observe` 看效果 → 下一步。
要走就 `g1_walk`（超过 0.5 m 自动拆段；手里有东西用 `carry=true`）；要抓就先 `g1_hand_shape` 定义手型，再在 `g1_step` 的帧里把手的值从 0 慢慢变到 1。
对应 sim 里跑通的套路（罐子入桶）：走到桌前 0.7 m → 看 → 走近到 0.15 m 并对正 → 前倾 0.3 rad、举手 → 看、定位罐子 → 伸手到罐子侧面 → 合手 → 抬 → 看手里有没有 → 收到胸前 → 转 90 度 → 一边走一边看桶 → 桶在前方 0.3 m 时伸到桶口上方 → 张手 → 看结果。

**第 2 步：把做通的动作写成程序，但眼睛留在回路里。** 技能 `autonomous-control`。它在 `code/<项目>/` 下写一个控制器（Python，`ctx.call("g1_step", ...)` 调的还是同一套工具），要求：分成可以单独跑的步骤；每一步重新定位物体、检查前提、检查结果；场景不对就停下来给报告和图片；**在关键点（碰之前、松手之前、东西可能被碰动之后）它自己看图再决定**，不盲跑。

**第 3 步：在真实场景上反复测。** 它调 `request_operator`（kind `reset`）请你把东西摆回去，然后跑控制器，看报告和关键帧，改代码，换布局再来。每一次都记到 `memory/RUNS.md`。没有正式评分，目标是连续多次干净成功。卡住了 `request_operator`（`help`）。

**第 4 步：把会的教给下一个 session。** 做通的流程写成 `skill-library/` 里可执行、带证据和图片的技能，`skill_library_merge` 合并到库里。先标 `draft`，验证过再升级，session 结束前必须做一次。

整个过程中它持续写 `memory/PROGRESS.md`（当前步骤、确认的结果、失败的尝试和教训、好用的参数、代码和图片路径、剩余预算、下一步）和 `memory/TIPS.md`。它的对话上下文会被自动压缩，压缩后它靠这些文件接着干。

## 四、它必须守的规矩（写进它说明书里的，G1 专用部分）

1. **钥匙、停住、停止。** 没钥匙不能动；`g1_hold` 随时停住；你的停止（`o`、SONIC 的 `O`、手柄 Select）让机器人软掉坐下。停止、拔钥匙、摔倒之后它不许自己恢复，只能报告并等。重新上钥匙后先 `g1_status`、`g1_observe`。
2. **每次调用都以一个可以保持的姿势结尾。** 机器人会一直跟踪最后一帧，所以不许停在迈步中间；每次从测得的关节出发，绝不从零开始（一帧全零会把所有关节拉到零位）。
3. **小步、实测。** 控制器只是大致跟踪，走一段会漂几十厘米；每次动作短到能在中间观察；每个动作的效果用场景量出来；跟踪误差或倾斜在涨 = 碰到东西或要摔：停、退、重新看。
4. **手按比例合，力很大。** 0 张开、1 握拳；只在拇指和手指之间确实有东西时才合；手指没到位 = 碰到东西了。
5. 通用规矩：每个动作都是物理的、不可撤销的，宁慢勿快；拒绝是一堵墙，不许找绕过的路，不许通过工具以外的任何途径接触机器人、控制器、相机；拿不准就不动，把原因写进 `memory/PROGRESS.md`。

## 五、你和它怎么互动

| 你想 | 怎么做 |
|---|---|
| 告诉它这个 session 做什么 | 开 session 前写 `task.md`（物品、位置、目标、禁区、什么时候来问你），`configure_session.py --task-file task.md`。越具体它越少瞎试 |
| 中途改任务、给提示、让它停 | 直接在 agent 终端（`start_agent.sh` 那个窗口）打字。它是普通的 Claude Code 对话，随时能插话："先只做罐子"、"桶在你左后方 1.5 m"、"停下别动"。这和控制台的 `r` 是两条不同的路：终端是**对话**（它当成你的新指令来读，内容随意）；`r` 是**回答请求**（只对它正在等的那一条 `request_operator` 有效，内容固定是 done）。它在等 `request_operator` 时终端里打字它也看得到，但它那个工具调用还卡着，要么你按 `r` 放它走，要么等它超时（默认 15 分钟） |
| 回答它的请求 | 控制台 `r` = 给它正在等的那条 `request_operator` 回 "done"（`reset` 类回 "Scene reset done."）。这条回答是作为**工具返回值**回到它手里的：它调 `request_operator` 后程序就卡在那里每秒查一次回复文件，`r` 写了回复它就继续。要说别的内容，在 agent 终端里打字 |
| 看它在干什么 | dashboard（画面、姿态、请求）；`<session>/mcp.jsonl`（每一次工具调用和回复）；`agent-workspace/runtime/frames/`（它看过的每张图）；`memory/PROGRESS.md`（它自己的进度笔记） |
| 让它暂停 / 继续 | 空格。它感觉到的是"下一个调用被拒"，然后等你 |

## 六、心里要有数的几件事

- **它一步要想几秒到几十秒。** 一个"看、定位、伸手、看"的循环在 sim 里是 30 到 90 秒；一整个罐子入桶 10 到 15 分钟，大部分时间是它在想和看，不是机器人在动。
- **它不能后退、不能横移、不能让机器人坐下再站起来**：这些工具里没有。走错了只能转身绕。
- **它不会替你做安全判断。** 它遵守规矩，但"带子该不该摘"、"脚站没站好"是你看的。
- **它会反复试同一个抓取**，每次失败可能把东西越推越远（sim 里纸团就是这样丢的）。`task.md` 里可以写"同一个物体失败两次就停下来问我"。
- **第一次用真机时建议 `task.md` 只写一件事**（比如：把罐子拿起来再放回去），让它先把前几节的检查跑一遍，技能库里留下真机的走路标定和相机标定，再给长任务。
