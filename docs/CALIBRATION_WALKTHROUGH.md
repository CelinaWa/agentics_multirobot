# 第一次标定（motion check）：机器人每一步会做什么

对应 `bash scripts/g1_check_all.sh <session>`（逐步、每步前按 ENTER）和 `scripts/g1_motion_check.py <session> <step>`（单步）。
所有动作都经过 agent 用的同一个 backend 和同一套保护（arming、倾角 60° 停、链路超时停、关节步长限制），所以这一遍也在验证保护本身。
每步的数字追加到 `<session>/runtime/characterization/g1_motion_check.jsonl`，最后 `report` 汇成表，抄进 `G1.md`。

Sim 里这整套流程完整跑过 6 遍（2026-10-29，前 4 遍吊着按 `s`，第 5 遍脚着地但 sim 弹簧吊带还压着它、上身起振，第 6 遍脚着地、`s` 后立刻把吊带淡出，录像见文末，都没有摔）；真机数字一个都还没有。下面"预期"一栏是 sim 的值，真机对不上就停下来看。

**为什么脚要先着地再按 `s`**：脚不着地时 SONIC 没有地面反力，腿在空中前后乱蹬（sim 里踝 ±0.7 rad、腰 pitch 0.1–0.57 rad、倾角到 9°，hold 的跟踪 RMSE 0.45 rad），旁边的人会被踢到，落地时也是这个怪姿势。前 4 次 sim 录像就是吊着按的 `s`（录像里能看到），之后改成脚先着地。腰在空中可以停在限位之外（限位 0.52），所以 hold 接管时会把实测关节夹进限位内再当参考（最多动几百分之一弧度）。

## 准备

- 机器人挂在龛架/吊带上（开机和 SONIC 启动时脚离地约 20 cm；SONIC 启动时会用 3 s 把全身拉到标准站姿，这一下要吊着）；SONIC 窗口显示 `Init Done`；console 窗口开着（`scripts/g1_console.py --session <root>`）。
- 一个人手放在停机上（console `o`、deploy 的 `O`、手柄 Select）。console 的 SPACE 在任何一步里都能让机器人暂停并解除 arming。
- 开始时**不要**按 `s`：前两步要在"没控制、没 arming"的状态下测。

## 第一组：脚承重，带子松着挂

| 步 | 机器人做什么 | 时长 | 测什么 | sim 预期 |
|---|---|---|---|---|
| `status` | 什么都不动。连 backend，打印到 SONIC 的链路、状态消息年龄、是否 armed、相机状态 | 1 s | 链路通、state 每 20 ms 一条 | state age < 0.05 s |
| `disarmed` | 什么都不动。发一帧 `g1_step`，必须被拒绝（未 arming） | 1 s | 保护第一层 | 文本 "motion is not armed" |
| **操作**：**先放吊架到脚承重、带子还轻轻托着**（此时它是 `Init Done` 时拉成的刚性站姿，没有平衡，带子全松会倒），**再** console 按 `s`；**按完 `s` 几秒内把带子彻底放松到不受力**（挂着兜底）。机器人在原地站住（stand 模式不迈步）。等它不动了按 SPACE（arm）。**脚离地不要按 `s`；`s` 之后带子不能再受力。** | | | | |
| `hold` | 什么都不动，站 10 s | 10 s | 关节漂移、倾角范围、控制器自身跟踪误差（agent 之后不能把这个当成接触） | 带子不受力时：漂移 < 0.01 rad、倾角 1.3°、腰 pitch 纹丝不动（吊着按 `s`：漂移 ~1 rad、倾角到 9°；带子还拉着骨盆：上身 2 Hz 起振、腰 pitch 0.4 rad） |
| `arms` | 右臂、再左臂，依次：肩 pitch −0.3 rad（手向前抬）、肘 +0.3 rad、腕 pitch +0.3 rad；每个 1.5 s 出去、停 0.5 s、1.5 s 回来 | ~35 s（6 个动作） | 关节到位量、手心位移（指令 vs 实测 FK，cm）、回位残差、倾角 | 到位 0.23–0.29 rad、手心误差 0.7–1.5 cm、倾角 ≤ 1.2°、腰 pitch ±0.03 rad |
| `waist` | 腰 yaw +0.2 rad 再回；腰 pitch +0.15 rad（小前倾）再回。腰已经靠近限位时自动改成往有余量的方向转，并打印实际角度 | ~15 s | 到位量、峰值倾角、朝向变化 | yaw 到位 0.05–0.08 rad（SONIC 不太跟腰 yaw）、pitch 到位 0.16，倾角 < 1° |
| `hands` | 右手完全闭合（1 s）、停 1 s、张开；然后左手 | ~10 s | 手指关节到位 vs 目标 | 闭合误差 ~0.19 rad、张开 ~0.06 rad（sim Dex3 kp 1.5；真机 kp 8 会更紧） |
| `pause` | 右肩 pitch −0.5 rad、1.8 s；**你在它一开始动就按 SPACE** | 2 s + 3 s 观察 | 停机延迟、停后超调、停后 3 s 漂移。**做完 session 是未 arming 状态** | 延迟 < 0.01 s，超调 ≤ 0.08 rad，停后 3 s 漂移 0.002 rad |

## 第二组：脚着地（机器人自己站）

**操作**：带子保持松着挂；四周清 1.5 m。console SPACE 重新 arm。

| 步 | 机器人做什么 | 时长 | 测什么 | sim 预期 |
|---|---|---|---|---|
| `turn --repeat 2` | **会迈步**。第一次 `g1_walk` 先做 planner 热身：左转 15°、右转 15°（各约 5 s）。然后 +30°、−30°，重复两轮。每次转身是慢走式（0.1 m/s 向前挪 0.1–0.2 m），转完 planner idle 1.5 s，机器人安静后 hold 接管 | ~60 s | IMU 前后朝向差 vs 指令、每次用时、倾角 | +30° 实测 17–33°、−30° 实测 −22° 到 −25°（偏少、散），倾角 3–5°，带热身的第一次 13 s、之后 5 s |
| **操作**：脚尖位置贴胶带，前方清 2 m。 | | | | |
| `walk --repeat 2 --forward 1.0` | **会迈步**。向前走 1.0 m，0.3 m/s（0.5 m 一段，每段 planner 重启），走完 idle、安静后 hold 接管；每次问你卷尺读数 | 2 × ~15 s | 实走/指令比、planner 自报前进量、朝向漂移、倾角 | 0.5 m 指令 planner 自报前进 0.38–0.40 m、14 s、倾角 ≤ 4.7°、朝向漂移 ≤ 3°（实走比例要真机卷尺量） |
| **操作**：吊带松、四周 1 m（蹲时身体后退 10–15 cm）。 | | | | |
| `crouch` | 依次蹲 0.1、0.2、0.3 m：3 s 下、停 2 s、3 s 起；某一级倾角超 15° 就不做更深 | ~30 s | 骨盆高度估计 vs 站立 0.77 m、倾角、起身残差 | 骨盆估计 0.80 → 0.685 / 0.57 m（0.1/0.2），蹲着倾角 3–6°，起身后 ≤ 2.4°；0.3 m 下降 0.29 m、倾角 7°、后退 19 cm |
| `camera` | 什么都不动。拍一帧，给出内参、backend 假设的相机位姿、深度有效比例、视野里水平面的高度（level 坐标系）；传入卷尺量的骨盆高和桌面高就算误差 | 2 s | 相机几何对不对 | 地面/桌面误差 < 2 cm |
| `report` | 什么都不动。把每步最新结果拼成表 | | 抄进 `G1.md` | |

结束时机器人仍由 SONIC 站着。要么接着 `bash scripts/g1_up.sh agent --task-file ...`（不要再按 `s`），要么收工：挂回吊带，console `o`，`tmux kill-session -t g1`。

## 哪些时刻最可能出事

- `s` 那一下：stand 模式不迈步，但接管瞬间腿会伸直一下，带子要兜着。脚离地按 `s` 的话 SONIC 在空中乱蹬（sim 里踝 ±0.7 rad、倾斜 9°），落地时还是那个姿势，这就是 sim 里"放手后窄步态摔"的来源（5–10%）。sim 对比：吊着按 `s` 腿速 35 rad/s、永远安静不下来；脚着地但 sim 的弹簧吊带还拉着骨盆：轻微踩踏，之后上身 2 Hz 起振（腰 pitch 0.4 rad）；脚着地、`s` 后把吊带淡出到不受力：hold 纹丝不动，arms 倾角 ≤ 1.2°。**`s` 之后带子必须真的不受力**：任何持续拉/压骨盆的力，策略都会去对抗，就会起振。带子**松但一定还挂着**：`Init Done` 之后机器人只是被 PD 锁在标准站姿上的刚体（deploy 的 `InitControl` 用策略增益把关节拉到 `default_angles`，指令线程从一开始就在发），没有平衡反馈，推一下就倒。官方 teleop 文档的原话也是 "stand loose but standing, somehow slack on gantry"，然后才启动策略。sim 里试过"完全摘带子再按 `s`"：带子一松，被 PD 锁住的刚体 1 s 内就向后倒了（sim 自动复位后 `s` 才站起来）。真机上同样会倒，所以**带子只能松、不能摘**。
- `turn` 的第一次热身：sim 里 SONIC 第一步有约 5–10% 扑倒（策略本身）。吊带一定挂着。
- 任何一次走完机器人还在原地踏步：backend 会先对齐 planner 朝向、再让它慢走一步重置步态（约 20 s 内），接不回来会报错让你处理（看它停下，或挂带子按 `o`）。它**不会**硬把 hold 压到踏步的机器人上。
- `crouch` 0.3 m：sim 里倾角 7°、后退 19 cm。真机第一次只做 0.1（`--drops 0.1`）。

## 一天只有一分钟时

`bash scripts/g1_check_quick.sh <session>`：`status`、`hold`、`arms` 三步，对照 `G1.md`：跟踪 RMSE 或手误差翻倍、倾角往上爬，就不要启动 agent。
